# Goohub architecture and workflows

Goohub is a static monorepo, not a single application. Web pages are plain HTML/CSS/JavaScript, browser extensions are independent packages with their own manifests, and `GooneeBrowser/` is a separate Gradle Android project. There is no shared framework or dependency install step at the repository root.

## Repository map

### Website and Playground

- [`index.html`](./index.html) is the repository-root landing experience. It loads shared styles and scripts from `playground/`.
- [`playground/index.html`](./playground/index.html) is a second, standalone version of the experience. It shares many files with the root page, but the markup has drifted; changes to shared behavior should be checked against both entry points.
- [`playground/script.js`](./playground/script.js) initializes the visual effects and interactive features. The page also loads the marketplace data, GoRum tools, social sharing, metadata and analytics scripts listed near the end of each HTML page.
- `playground/twittercss/` contains an X/Twitter theme-extension prototype. It is not identical to the separate package under `gooextension/extension/`.
- The root page and Playground can be previewed from a local static server:

  ```sh
  python -m http.server 8000
  ```

  Open `http://localhost:8000/` or `http://localhost:8000/playground/`.

### Bookmarklet tools

- [`bookmarklettool/loader.js`](./bookmarklettool/loader.js) creates the floating SharkTool panel in the current page.
- [`bookmarklettool/manifest.json`](./bookmarklettool/manifest.json) is the local list of tools. Script files in the same folder are loaded sequentially when selected.
- The loader derives the manifest and asset base from its own script URL. For deployment, publish `loader.js`, `manifest.json`, `panel-theme.css`, and the referenced tool scripts together in one directory. The bookmarklet URL must point to the deployed `loader.js`.
- The loader stores selected tool IDs and page-theme preference in the current site's `localStorage`. A strict Content Security Policy on the destination site can prevent the loader or its scripts from loading.
- [`bookmarklettool/Freetool.md`](./bookmarklettool/Freetool.md) is the user guide; [`bookmarklettool/DEV_GUIDE.md`](./bookmarklettool/DEV_GUIDE.md) describes maintenance and deployment.

### Browser extensions

Each folder with a `manifest.json` is an independent extension package. For local testing, open the browser's extension management page, enable developer mode, and choose **Load unpacked** for the relevant source folder.

| Folder | Package | Runtime flow |
|---|---|---|
| [`gooextension/extension/`](./gooextension/extension/) | X/Twitter Multi-Theme, Chromium Manifest V3 | `popup.html` / `popup.js` reads and saves the selected theme in `chrome.storage.sync`; `service_worker.js` inserts the matching local CSS file for `x.com` and `twitter.com`. |
| [`gooextension/final/`](./gooextension/final/) | Shark Tools Floating Menu | `content.js` creates the page UI, `background.js` handles extension storage/messages and script execution, and `setting.html` / `setting.js` manage tools and settings. The current build script packages Chromium and Firefox variants. |
| [`Gooscript/Gooscript/`](./Gooscript/Gooscript/) | Older Shark Tools package snapshot | It overlaps with `gooextension/final/`; its manifest and background script match, while content/settings files differ. It is not generated by the current build script, so do not assume it stays in sync. |
| [`GooneeXeruda/GooneeXeruda/`](./GooneeXeruda/GooneeXeruda/) | Eruda DevTools | The background worker injects the locally bundled Eruda UI. The manifest requests the powerful `debugger` permission; review the requested permission before installing. |
| [`playground/twittercss/`](./playground/twittercss/) | X/Twitter theme prototype | A separate popup/service-worker implementation with the same manifest identity as `gooextension/extension/`; use `gooextension/extension/` as the maintained package for that extension. |

#### Shark Tools packaging

The editable Shark Tools source is in `gooextension/final/`. From that directory, run the PowerShell build script:

```powershell
.\build-extensions.ps1
```

It stages unpacked builds in `build/chrome/` and `build/firefox/`, then writes the ZIP/XPI packages in `build/`. It removes only those generated staging folders before rebuilding; existing release archives remain until replaced. The Chrome/Edge package uses Manifest V3; Firefox uses the separate Manifest V2 file. The `.crx`, `.xpi`, and ZIP files are distribution artifacts, not the source of truth.

The X/Twitter extension in `gooextension/extension/` is loaded unpacked from that folder; its popup stylesheet is local and is referenced directly by `popup.html`.

### Cybersecurity LAB

- [`LAB/index.html`](./LAB/index.html) is the enhanced LAB landing page and links learners into the lessons. `LAB/lab.html` is a legacy page that points back to the newer interface.
- `LAB/modules/` contains standalone lesson pages such as SQL Injection, XSS, CSRF, network forensics, ciphers, and simulated DDoS/MITM material.
- `LAB/docs/` has additional documentation and the Gambling API simulation. `GamblingAPI_lab.html` loads its shared front-end source from `LAB/gambling-lab.js` through a small loader, while `LAB/docs/sw-gamble.js` simulates the `/api/*` endpoints. It is a local educational simulation, not a real service.
- To serve only the LAB on Windows, run `.\serve-lab.ps1 -Port 8000` from `LAB/`. From a repository-root static server, open `http://localhost:8000/LAB/index.html`.
- See [`LAB/README_DEPLOY.md`](./LAB/README_DEPLOY.md) and [`LAB/README_GamblingLAB.md`](./LAB/README_GamblingLAB.md) for additional exercise details.

### Android browser

[`GooneeBrowser/`](./GooneeBrowser/) is a Kotlin/Android Studio project. Gradle configuration is in `settings.gradle.kts`, top-level `build.gradle.kts`, `app/build.gradle.kts`, and the version catalog under `gradle/`. The app uses a WebView, View Binding, AndroidX/Material components, and the Google Generative AI SDK.

From `GooneeBrowser/`, use Android Studio or the Gradle wrapper:

```sh
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
```

An Android SDK is required. AI credentials should be supplied locally through the app settings; do not commit real API keys. See [`GooneeBrowser/README.md`](./GooneeBrowser/README.md).

### Other utilities

- `js/config.js` provides shared page configuration.
- `Gooscript/`, `GooneeXeruda/`, `bookmarklettool/`, and `gooextension/` are separate extension/script products; their similarly themed UI does not imply shared runtime code.
- `*.crx`, `*.xpi`, `*.apk`, and folders named `build/` are prebuilt or staged outputs and may not reflect the current editable sources.

## Validation

The repository smoke tests use Node's built-in test runner and need no dependency installation:

```sh
node --test tests/project-quality.test.js
```

They verify bookmarklet manifest paths, X/Twitter extension assets/theme files, and JavaScript syntax for the maintained files touched by this work. The older browser-oriented visual/performance/compatibility suites in `playground/tests/` are not currently wired to a browser automation runner; they should not be described as CI coverage.
